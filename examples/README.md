# Example data

## `synthetic/` — SYNTHETIC reads (not biological data)

| File | Content |
|------|---------|
| `SYNTHETIC_nanopore_reads.fastq.gz` | 400 long reads, log-normal lengths (N50 ≈ 5 kb), qualities around Q14 |
| `SYNTHETIC_illumina_R1_001.fastq.gz` / `_R2_001` | 2,000 read pairs of 150 bp, AT-rich composition, quality decaying towards the 3′ end |
| `SYNTHETIC_nanopore_signal.pod5` | POD5 raw signal: 5 reads of Gaussian noise (299,000 samples at 5 kHz, 59.8 s), one acquisition whose free-text fields all say `SYNTHETIC` |

These files are generated by `scripts/make_synthetic_reads.py` (deterministic seed).
Sequences are **uniformly random** and have no biological meaning; every header
contains the word `SYNTHETIC`. Use them to try the import → read statistics →
report flow, and in automated tests. Do not interpret their results biologically.

Regenerate with:

```bash
python3 scripts/make_synthetic_reads.py examples/synthetic
```

The POD5 file is written by `scripts/make_synthetic_pod5.py` with the official `pod5` Writer API
(needs `pip install "pod5==0.3.49"`; fixed numpy seed, timezone-aware timestamps):

```bash
python3 scripts/make_synthetic_pod5.py examples/synthetic   # refuses to overwrite an existing file
```

POD5 bytes are **not reproducible**: every write gets a random file identifier and section marker,
so a regenerated file has a different SHA-256 even though its signal and metadata are identical.
Tests must not assert its checksum; they check its content instead.

## `synthetic-genome/` — SYNTHETIC genome and simulated reads for assembly

A circular 300 kb chromosome with two identical 5 kb repeat copies and a circular 15 kb plasmid at two
copies, with Nanopore-like reads (about 50×, median 6 kb, about 4 % errors with calibrated qualities)
and Illumina-like 2 × 150 bp pairs (about 60×, inserts 350 ± 50 bp, 0.5 % substitutions). The true
genome is `reference.fasta`, so assembly results can be checked against it. Only its README (model,
parameters, realised statistics and checksums) is in git; generate the files (about 40 MB, a few
seconds) with:

```bash
python3 scripts/make_synthetic_genome.py examples/synthetic-genome
```

Options set the sizes, depths, error rates and seed (`--help`); tests use a 60 kb chromosome.

To try the assembly workflow with it: create a sample with technology *Oxford Nanopore*, import
`ont.fastq.gz`, compute read statistics, then open **Assembly → New assembly…**, choose the read type
(ARVA suggests `--nano-hq` from the qualities, as a heuristic), review the summary and start. With
Flye 2.9.3 the default data assemble into the two replicons at their exact lengths, both reported
circular, the plasmid at about twice the chromosome's coverage; the charts, contig table and graph view
show this, and the graph shows each replicon as a segment linked to itself. Import `reference.fasta`
into the same sample to evaluate the assembly with QUAST against the true genome (genome fraction just
under 100 % for a rotated circular contig is explained in the QUAST card). Run a second assembly (for
example with other settings or a Filtlong-filtered copy of the reads) to see the comparison table and
overlaid cumulative curves.

For real bacterial data, public runs from the ENA/SRA (for example Nanopore or
Illumina runs of *Staphylococcus aureus* isolates) can be downloaded and
imported directly.
