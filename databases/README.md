# Reference databases

Reference databases are recognised, registered, downloaded, verified and recorded by ARVA's **Database Manager**
(Tools & Databases → Reference databases; API under `/api/v1/databases`), not stored in this repository. Databases
you already have stay where they are (for example on an external disk, added read-only with
`scripts/start.sh --add-databases`); downloaded versions go into a database folder ARVA may write to
(`scripts/start.sh --databases-dir`, `ARVA_DB_DIR`; Docker: `/databases`). How to use them:
[docs/installation.md](../docs/installation.md#reference-databases-database-manager).

The kinds and their facts are in `apps/api/app/services/database_kinds.py`, the downloadable versions in
`apps/api/app/services/database_catalogue.py`, and the detectors in `database_detect.py` and
`reference_collections.py`. Every fact was checked (Bakta on 2026-10-28, the others on 2026-10-29) in the tool's official documentation or source
code, or in the publisher's records, cited below; what could not be confirmed is listed as such. ARVA only
downloads a version when the publisher offers a stable, versioned archive with a published checksum; every kind can
be registered where it already is. ARVA never writes into a registered folder and never redistributes the Ridom
spa-type files.

## Versions and how they are known

The version is read from the database's own files where the kind writes it; otherwise you declare it and ARVA labels
it *declared by the user*; CheckM2's DIAMOND file can be identified by the SHA-256 CheckM2 publishes. A reference
genome collection's version is its source and date (declared) plus a fingerprint of its sorted accession list.
Several versions of a kind can be kept; one is the default; each job records the kind, version, how the version was
known, the content checksum (after a full verification) and the path.
